# v10.2.27 mechanical-kernel resolution

Production simulations request a mechanical configuration and crack-growth
coverage. They do not require a preserved `FAMILY_JSON`, snapshot archive, or
load-invariance archive.

## Default single-front workflow

For a missing or insufficient kernel, the resolver automatically:

1. fingerprints the requested orientation, specimen dimensions, initial crack and
   notch geometry, boundary-condition profile, mesh, process-zone length and bins,
   interaction length, elasticity policy, crack increment, and topology mode;
2. enlarges the default specimen when the requested path coverage would not fit;
3. generates an extension-state table through the required path coverage;
4. runs an internal deterministic, unshielded mechanics-only geometry driver;
5. serializes new fixed-crack FEM states from the live solver;
6. recalculates load invariance for every state;
7. derives normalization from the newly captured engine configuration;
8. builds and validates the signed active-kernel family;
9. caches it under `runs/v10_2_27_kernel_cache/<configuration-fingerprint>/`.

The mechanics-only geometry driver is generated by the code and is not one of the
scientific material parameterizations. For a single nonbranching front, material
kinetics determine when a prescribed extension is reached; the frozen FEM operator
is recalculated at the requested crack geometry.

Changing theta, initial crack length, specimen dimensions, notch geometry, mesh,
process-zone geometry, interaction length, elasticity, or another mechanical
coordinate creates a new fingerprint and triggers a new calculation. Target
extension remains a coverage coordinate while it fits the configured specimen. If
additional coverage requires a larger specimen, the enlarged domain correctly
becomes a new mechanical configuration. A shorter campaign may reuse a longer
validated cache only when the complete mechanical fingerprint is identical.

## Optional caches

A family or portable mechanics archive may be supplied explicitly as an
acceleration only. It must carry the exact mechanical-configuration fingerprint and
pass field-level checks. Legacy archives without that provenance, including the old
100 µm/40-bin theta=30 capture, are rejected. A leftover `FAMILY_JSON` environment
variable is ignored during normal runner resolution unless an override is explicitly
requested.

## Partial campaigns

Retained material cases may be combined with newly run cases only when their
parameter-transfer audit records the same mechanical-configuration fingerprint as
the resolved family. Cases created before that provenance field existed are not
silently accepted; the affected material set must be rerun with one common kernel.

## Current limitation

The built-in automatic provider is for one unbranched front. Branching requires a
registered `topology_cached` or `direct_fem` provider because branch interactions
cannot be represented by an extension-only atlas. The code fails at that model
capability boundary rather than substituting a single-front reference condition.
